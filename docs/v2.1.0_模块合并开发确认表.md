## 二、模块三（关联）核心机制

- **双向链接语法**：`@[Type:ID]`，Type ∈ {task, memo, item, photo, collection, location, ledger}。
  - 解析：`extractBiLinks` / `tokenizeBiLinks`（`bilink.js`）。
  - 反向索引：`store.setEntityRelations` 写 `biLinks`（双向），`store.relatedEntitiesFor(type,id)` 派生 `out`（我指向）/ `in`（指向我）。
  - 画布同步：关联落库后 `syncRelationCanvas` 生成语义连线。
- **五详情页接入**：Tasks / Backpack / Album / Map / Ledger 均新增「关联内容」按钮 + 双向关联 chips + 详情 Modal 的 `.rel-block`。
- **笔记内联引用**：`Notes.vue` 的 `@` 级联选择器插入 `@[Type:ID]`（`BiLinkText.vue` 负责差异化渲染），`CanvasNavigator.parseEntityRefs` 同语法解析画布节点引用。

## 三、模块六（插件）安全边界

- **本地 JS 插件**：`new Function` + `with(this)` 注入 Proxy 沙箱；白名单仅放行 `eoPlugin/console/定时器/Math/JSON/...`，**阻断** `window/document/localStorage/indexedDB/sessionStorage` 直操；仅授权 `network` 权限时放行 `fetch/XHR`。
- **URL 插件**：`iframe sandbox="allow-scripts"` + `srcdoc` 注入桥，`postMessage` 协议 `__eo:registerRoute/registerContextMenu/registerCanvasNode/toast/error`，右键项经 `__eoRun` 触发。
- **注册表**：`pluginRegistry`（reactive）管理 `routes/contextMenus/canvasNodes/errors/_iframes`；`mountEnabledPlugins` 在 `App.vue` onMounted 挂载已启用插件；本地代码从 `localStorage['eo_plugin_code_'+id]` 读取（不入库外泄）。
- **崩溃隔离**：插件运行异常经 `recordError` 入册，仅提示不白屏。

## 四、本次修复清单（阻断项）

| # | 问题 | 根因 | 修复 |
|---|------|------|------|
| 1 | `extractBiLinks` 解析返回 0 条 | 正则 `\[@(...)` 期望 `[` 在前，与文档/实际语法 `@[Type:ID]`（`@` 在前）顺序相反；`Notes.vue` 插入的也是旧序 `[@` | `bilink.js` 正则改为 `@\[(...)`；`Notes.vue` 插入串改为 `'@[' + ...` |
| 2 | `runLocalPlugin` 抛 `Strict mode code may not include a with statement` | `new Function` 体内注入了 `"use strict";`，而沙箱依赖 `with(this)` 重定向到 Proxy，strict 模式禁止 `with` | 移除体内 `"use strict";`，改为 sloppy 模式（被阻断的写入静默失败，反而更安全） |
